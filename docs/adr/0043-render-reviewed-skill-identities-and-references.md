# Render reviewed skill identities and references

Two independently useful Packs can publish different skills with the same native
name. A directory alias does not change the `SKILL.md` identity a host discovers,
and renaming only that identity can route another skill's unqualified calls or
relative links into the wrong Pack. Preserve both implementations through an
explicit, reviewed `skill-template` surface capability instead of inferring
references in arbitrary Markdown, code, or shell text.

A template binding declares `naming: native` or `naming: pack-surface`. The latter
resolves its default native name to `<pack-id>-<surface>-<binding-name>` before
explicit user aliases. This stable catalog policy avoids installation-order
renames and separates adaptations that compatibility discovery could otherwise
confuse. It never changes another installation, grants ownership of foreign
paths, or retries with an arbitrary suffix. Remaining collisions still block.

A source declares an intra-Pack native-name reference with
`{{packy.skill:<logical-id>}}`. Resolve it against the effective selected Pack's
bindings and explicit aliases. References to another skill require a direct
`requires` edge. The same token can appear inside a host invocation, a quoted
tool-call name, or a sibling path; the surrounding reviewed syntax stays intact.
A template's native frontmatter name follows its own effective binding. Missing,
malformed, excluded, unbound, or undeclared references fail before mutation.
Other source bytes and the immutable Catalog Snapshot remain unchanged.

Materialize a deterministic generated tree for templated skills in both global
and project scope. Preview exposes and observes the resulting native names and
seals the generated bytes, renderer identity, and source contract. Installed
receipts authorize only the exact final projection and its digest. Ordinary
freshness, drift, update, and removal protections apply; generated content does
not establish host authorization or successful model-backed execution.

This decision supersedes ADR 0041's rejection of installation-time prompt
rewriting only for explicit typed template rendering. Unreviewed rewriting stays
out of scope. Existing non-template content keeps its current projection and
conflict behavior. Manifest schema v3 gains one closed capability vocabulary
member, rather than a new format: older engines reject snapshots using the new
capability. Release the engine before publishing reviewed catalog adaptations.
