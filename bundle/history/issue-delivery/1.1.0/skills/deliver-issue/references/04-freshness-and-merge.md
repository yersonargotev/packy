# Freshness and merge

Immediately before merge, fetch and reobserve the issue, pull request, base
and head commits, reviews, conversations, checks, and GitHub merge state.
Require unchanged approval and materially unchanged issue authority, the exact
reviewed-and-validated head SHA, passing required checks, resolved substantive
advisory findings and review conversations, and every policy-required
protection condition. A material authority change returns to qualification.

If the base advanced, follow the repository policy and GitHub's current
mergeability state. Integrate the protected base only when currentness is
required; preserve published history without rebase or force-push. Such a
change is a new candidate and returns to final candidate proof and final review.

Merge through the repository's enabled protected path and a currently enabled
merge method. Do not bypass a gate or use an administrator override. Record the
method, exact candidate head, and GitHub-reported integration commit.

**Complete when:** GitHub reports a protected merge of the pull request whose
recorded head is the exact final candidate, and the method-specific integration
proof in the next phase can bind that candidate to protected base.
